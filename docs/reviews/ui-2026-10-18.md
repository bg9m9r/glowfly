# UI review, 2026-10-18

Four reviewers went through the UI snapshots in `crates/glowfly-app/tests/snapshots/` (about 550
screens viewed in all), two for visual design and two for UX, each taking half the files. Snapshot
names below are relative to that folder; code paths to `crates/glowfly-app/src/` unless they say
otherwise. The findings are as of commit `ef0e3c4a`; TODO.md tracks the work (Milestone 1 for
blockers and major findings, Later for the minor ones).

Already fixed or in progress when the review ran, and left out of it: cut-off branch labels in the
graph, branch menus that repeat the branch name, the squeezed Reset submenu, and drawer default
sizes and limits.

## Visual design, snapshots a–l

### Blocker

- **severity:** blocker
  **area:** Sidebar, ahead/behind counts (font glyphs)
  **problem:** The local-branch ahead count shows as `2□`: a missing-glyph box instead of an arrow. `ui/sidebar.rs:78/81` builds the text from `"{}↑ "` / `"{}↓"`, and the bundled font has no ↑/↓ glyphs (the same font gap CLAUDE.md lists for ▾ ✎ ↻). A first-time user reads this as a rendering bug, and every branch that is ahead of or behind its upstream shows it.
  **evidence:** `branch_menu.png` (row "search 2□"), `create_pr_dialog_push.png` (row "search 2□")
  **suggested fix:** Paint the arrows as shapes with `widgets::paint_icon`, next to a plain-digit label. Add a test that walks every UI string literal and every runtime-built label template and fails on any char the bundled fonts can't render, so the next ↑, ⇡, ✓ or ⚠ is caught in CI instead of on screen.

### Major

- **severity:** major
  **area:** Text truncation (systemic; same kind of problem as the cut-off branch labels)
  **problem:** Single-line text is hard-clipped at the column or row edge, often mid-letter, with no ellipsis and no tooltip. This happens in the graph message column (the body preview "Project lay", "Projec"), in resized columns ("Merge branch 'login-pa", "Fix build on Window", dates cut to "01/10/2026 @ 10:"), in sidebar issue rows ("#12 Crash on start when the coı", "AB#5 Sign in with a work accou", "PROJ-7 Sign-in page reject"), and in the search placeholder ("…narrow with autho"). Some places do add an ellipsis ("No branches yet. Fetch this remote to load …"), so the app is inconsistent with itself.
  **evidence:** nearly every graph snapshot (e.g. `annotate_tag_dialog.png`, `branch_menu.png`, `gitflow_section.png`), `graph_columns_resized.png`, `graph_column_drag_light.png`, `cherry_pick_banner_old_git.png`, `issue_panel_github_light.png`, `issue_panel_failed.png`, `issue_panel_jira_dark.png`, `issue_panel_azure_light.png`, `graph_search_author_picker.png`
  **suggested fix:** Use one `truncate_label(ui, text, max_w)` helper everywhere. It should end on a whole glyph with "…" and show a hover tooltip with the full text. For the message column, fade the body preview out over its last ~24px instead of cutting it. In sidebar rows that carry a right-hand badge (issue state), reserve the badge width first and then truncate the title.

- **severity:** major
  **area:** Graph column headers while search/filter is active
  **problem:** When the graph is filtered, the GRAPH column shrinks to roughly the avatar width and its header runs straight into the next one, so it reads "GRAPHCOMMIT MESSAGE" with no gap or divider. The header looks broken.
  **evidence:** `graph_search_filtered.png`, `graph_search_no_matches.png`, `graph_search_paths_partial.png`
  **suggested fix:** Give each header a minimum width of its label plus padding, clip it with an ellipsis, and always draw the column divider. Alternatively, hide the GRAPH header text when the lane area is narrower than the label.

- **severity:** major
  **area:** Buttons: primary/secondary/disabled hierarchy (systemic)
  **problem:** Nearly every button uses the same flat chip: a fill only slightly different from the panel, no border, small text. Dialogs give the confirming action (Create, Annotate, Start, Run, Mark resolved, Fork and add remote) exactly the same look as Cancel. A disabled primary ("Annotate", "Finish", "Create repository", "Create filter", "Clone") differs from an enabled one only by slightly greyer text. In the light theme the enabled and disabled chips are almost the same. The only emphasised button in the app is the green commit button, so the visual language is inconsistent with itself.
  **evidence:** `annotate_tag_dialog.png`, `gitflow_finish_feature_blocked.png`, `gitflow_start_release.png`, `init_dialog_new_folder.png`, `init_dialog_problems.png`, `confirm_run_program.png`, `conflict_markers_warning.png`, `fork_create_ready_light.png`, `forge_filter_dialog_problems.png`, `clone_service_no_accounts.png`, `file_history_not_on_disk_light.png` (enabled "Restore this version…" vs disabled "Open with default app"), `commit_box_options.png` (the one filled button)
  **suggested fix:** Define three button styles in one place: primary (accent fill, high-contrast text), secondary (subtle fill plus a 1px border), and disabled (no fill, 40% text, no hover). Use primary for the confirming action of every dialog and for the default action of each panel. Make destructive confirms (Delete, Discard, Run) a red primary.

- **severity:** major
  **area:** Dialog layout (systemic)
  **problem:** Modal content sits about 7px from the modal edge. The title, body and controls are all flush left at that inset, and the button row is left-aligned with no separation from the body. Field right edges don't line up inside the same dialog:
  - Init: the Folder field ends at about 845px, Browse at about 919px, and Initial branch / Copyright fields end at different points.
  - Clone: the path field and Browse stop short of the URL field.

Use a two-column form grid in which every input fills the value column, with Browse… placed inside that column. Use two standard widths (narrow ~420px for confirms, wide ~560px for forms) instead of per-dialog widths.

## Visual design, snapshots m–z

### Blocker

1. **blocker · Sidebar / ahead-behind counters: missing glyph shows as a tofu box**
   - Problem: The local-branch row builds its ahead/behind text from `↑`/`↓` characters (`ui/sidebar.rs:78-81`). The bundled font has no glyph for them, so a branch that is 2 behind shows `2□`. Every tracked branch that is ahead or behind will look like this, so most users will see it.
   - Evidence: `remote_branch_menu_tracked.png` (LOCAL › `search` row, right side shows "2□"). The test sets `behind = 2` (`snapshot_tests_remote_branch.rs:56`), and no other snapshot covers ahead/behind, so the regression slipped through.
   - Fix: Paint the arrows as shapes with `widgets::paint_icon` (as CLAUDE.md already says for ▾ ✎ ↻), or use a glyph the font has. Add an ahead-and-behind snapshot. While there, grep `ui/` for other non-Latin symbols put into text (`→` in `file_dialogs.rs:87` and the `pr_menu_items.rs` tooltip, `✔` in labels) and check each one renders. `✔` and `→` seem fine in the snapshots, but there is nothing that checks them automatically.

### Major

2. **major · Commit list: message column hard-clips with no ellipsis (same class as the cut-off branch labels)**
   - Problem: The dimmed commit-body preview after the summary is cut off mid-glyph at the Author column ("Project lay", "Project layout and C"). There is no ellipsis or fade, so it looks like a rendering bug.
   - Evidence: `main_dark.png`, `main_light.png`, `main_sand.png`, `main_high_contrast_dark.png`, `worktree_wip_menu.png` (the "Add app skeleton" row in every main-view snapshot).
   - Fix: Lay out the summary and body as one truncating text job, ending in "…" (or a short fade) at the column edge. Never clip text at a column boundary without an ellipsis.

3. **major · Other truncation and overflow in narrow regions (same class as the cut-off branch labels and the narrow drawer)**
   - Problem: Important text is truncated where there is room to wrap or to say less.
     - The empty-state message for a remote with no branches is cut off: "No branches yet. Fetch this remote to load …". The user can't read the instruction.
     - In German, the commit-panel header squeezes its actions to "Neu…", and "Nicht bereitgestellt (1)" crowds into the buttons.
     - The update-status pill truncates the version: "Downloading Glowfly 0.3.0…".
   - Evidence: `tag_menu.png` and `remote_group_menu_github.png` (REMOTE › backup/linus rows), `main_window_german.png` and `menu_bar_view_german.png` (right panel header), `status_update_downloading.png`.
   - Fix: Shorten the empty state to "No branches – fetch to load", or let it wrap to two lines. In the panel header, move the secondary actions (New file…, Discard all) into an overflow ⋯ menu once their labels no longer fit. Size the status pill to its content, which can be done safely there.

  **problem:** One action is labelled differently from screen to screen. Creating a repository is "Init…" (File menu, repository menu) and "Start a new repository" (welcome). Opening is "Open repository…", "Open…" and "Open a repository". Stash removal is "Delete" (sidebar), "Delete stash…" (palette) and "Drop stash" (`palette_kinds.rs:57`).
  **evidence:** `menu_bar_file.png`, `repo_menu.png`, `welcome.png`, `stash_menu.png`, `state/palette_kinds.rs:48-57`.
  **suggested fix:** Pick one user-facing verb per action ("New repository…", "Open repository…", "Delete stash") and use it in menus, the palette, the welcome screen and job names.

- **severity:** minor
  **area:** Command palette default list
  **problem:** With an empty query, the palette opens on "Add remote…", followed by an arbitrary-looking order. Recently used commands (`palette_recent.png`: "Theme: Light", "Refresh") are mixed in with no "Recent" heading, so the user can't tell recents from the static list.
  **evidence:** `palette.png`, `palette_recent.png`.
  **suggested fix:** Group the empty-state list under headings: "Recent", "Suggested" (Pull, Push, Commit, Create branch…, chosen from the current state), then everything else.

- **severity:** minor
  **area:** Welcome / first-run validation timing
  **problem:** The first wizard step shows "An email address has an @ in it." in red before the user has typed anything; both fields are still empty placeholders.
  **evidence:** `welcome_identity_missing.png`.
  **suggested fix:** Validate when the user leaves the field or presses Continue, never on an empty, untouched form.

- **severity:** minor
  **area:** Error text with git jargon
  **problem:** Some dialogs show raw git internals to the user. The safe.directory dialog proposes adding `%(prefix)///nas/team/app` to the global config. The publish error reads "Repository creation failed. name already exists on this account" (lowercase, two sentences joined awkwardly). Repo sync shows "Could not read from remote repository." with no next step.
  **evidence:** `repository_owned_by_another_user.png`, `publish_dialog.png`, `repo_sync_running.png`.
  **suggested fix:** Describe the effect in plain words ("Glowfly will mark \\\\nas\\team\\app as safe in your git settings") and hide the literal value behind "Details". Rewrite service errors into a sentence that suggests what to do ("A repository called demo already exists on ada — choose another name.").

- **severity:** minor
  **area:** Routine success toasts
  **problem:** A background fetch produces a "Fetch succeeded" toast as well as the useful "main is 2 commits behind origin/main · Pull" alert. The routine one adds noise, and in the default bottom-left position both cover the branch list.
  **evidence:** `toast_behind_alert.png`.
  **suggested fix:** Don't toast routine successes of background or auto operations (log them only). Keep toasts for user-started jobs and actionable alerts, and move the default location away from the sidebar (for example bottom-right or the status bar).

- **severity:** minor
  **area:** Status bar update failure
  **problem:** "Update failed · Try again" gives no reason (network, checksum, disk), and the chip is the only place this appears.
  **evidence:** `status_update_failed.png`.
  **suggested fix:** Show the reason in the chip's tooltip, with a "Details" link to the error log or the Preferences Updates section.

- **severity:** minor
  **area:** Sidebar counts
  **problem:** The REMOTE header shows "0" while two remotes (origin, backup) are listed under it, because the count is of remote branches and not remotes. A first-time user reads it as "no remotes".
  **evidence:** `tag_menu.png`, `tag_delete_remote_confirm_light.png`, `remote_add_dialog.png` ("REMOTE 2" with 3 remotes).
  **suggested fix:** Count remotes in the header (or show "2 remotes · 0 branches" in a tooltip), or hide the count while no branches have been fetched.

- **severity:** minor
  **area:** Repository dropdown grouping
  **problem:** The repository menu mixes primary actions (Open, Clone, Init), navigation (Dashboard, an unexplained label), bulk tools (Fetch or pull repositories), list maintenance ("Remove missing entry (1)", "Clear recent") and favourites in one long popup. Recent entries show full paths, and a missing entry is greyed with no explanation.
  **evidence:** `repo_menu.png`, `repo_menu_actions.png`.
  **suggested fix:** Put Favorites and Recent first (what users open most), then Open / Clone / New, then a "Manage" submenu for Find in folders, Fetch all, Remove missing and Clear recent. Show the repository name in bold with the path as weak secondary text, and add a "not found" note to missing entries as `welcome_repos.png` already does.

- **severity:** minor
  **area:** Submodule status legend
  **problem:** Submodule rows use seven different dot shapes and colours (filled green, filled amber, hollow grey, hollow amber, ringed amber, red slashed, plus-ring) and nothing explains them. Clean rows (libs/core) have no text, so their meaning rests on colour alone.
  **evidence:** `submodules_section.png`, `submodules_section_light.png`.
  **suggested fix:** Give each row's dot a tooltip with its state, and give clean rows a quiet "up to date" text, so no state is shown by colour alone.

- **severity:** minor
  **area:** Shortcut sheet clipping
  **problem:** The Keyboard shortcuts modal has a fixed height. The last visible row is cut in half and no scrollbar shows, so users may not realise the list scrolls.
  **evidence:** `shortcut_sheet.png`.
  **suggested fix:** Always show the scrollbar (or a fade at the bottom edge), and size the dialog to the window height.

- **severity:** minor
  **area:** Fixed-width dialogs (same class as the reported squeezed and narrow panels)
  **problem:** Every modal is fixed at 460 px (`modals.rs:61`). Content with long paths or lists wraps awkwardly or gets truncated: the stored-module path and commit list in Remove submodule, long config values in the trust prompt, and the merge options in the PR overview. Users can't resize them.
  **evidence:** `submodule_remove_confirm.png`, `trust_prompt.png`, `worktree_remove_force_light.png`, `ui/modals.rs:61`.
  **suggested fix:** Give dialogs a minimum and maximum width that adapts to their content (for example 460–720 px, or a share of the window). Let long-content dialogs (trust, remove submodule, apply patch) be resizable, and elide paths in the middle with a full-path tooltip.

- **severity:** minor
  **area:** Rebase banner layout in the narrow details panel
  **problem:** The banner wraps its four buttons over two lines ("Edit remaining steps…" drops to its own row) and the conflict line breaks mid-sentence. It's cramped even at the default panel width.
  **evidence:** `rebase_banner_conflict.png`, `rebase_banner_command.png`.
  **suggested fix:** Put Continue as the primary button, and move Skip, Abort and Edit steps into a split-button or overflow menu; see also the blocker about showing this state outside the details panel.

- **severity:** minor
  **area:** Tabs strip
  **problem:** The open-tabs and recently-closed list sits on a lone "▾" at the far right edge of the window, far from the tabs. Grouped tabs are marked only by a coloured underline, with no group name or chip, so the grouping is hard to read.
  **evidence:** `tabs_list.png`, `tabs_grouped.png`.
  **suggested fix:** Put the tab-list button right after the last tab (next to "+"). Give each group a named, coloured header chip that can be collapsed.
